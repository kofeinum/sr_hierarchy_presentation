Система именования

У динамического объекта каждая деталь двигается отдельно. Чтобы это работало в Omniverse — дерево объектов строится по чёткому правилу, а имена говорят сами за себя.

Пример: SKU-CLIENT-CAR_SEAT-SR
SR
Зачем система именования?
Имя объекта должно отвечать на три вопроса — без открытия дерева сцены:
01
Какой материал?
Начало имени геометрии — это точное имя её материала. Сразу видно, что должно быть назначено
metal_aa00G
02
Под каким хелпером?
Конец имени геометрии повторяет суффикс её родительского хелпера. Место в дереве читается из имени
metal_aa00G
03
Двигается или нет?
Буква G в конце — геометрия подвижная. Без G — стоит на месте. Хелпер с H — подвижный узел
metal_a  vs  metal_aa00G
Итог
Валидатор и автофикс читают имена объектов — и не тратят время на разбор дерева. Если имя построено по правилу — ошибок не будет.
Пять типов объектов в SR-сцене
Корневой хелпер
SKU-CLIENT-CAR_SEAT-SR
Точка привязки всего объекта. Имя = имя файла сцены. Единственный прямой потомок корня дерева Max.
Статичный хелпер
base_a
Обязательный первый дочерний хелпер корня. Контейнер неподвижной геометрии и стартовая точка всей динамики.
Подвижный хелпер
slide_a00H
height_b00a00H
Ось движения для одной детали. Содержит букву типа, номер экземпляра и ссылку на родителя. H на конце — маркер (подробнее на след. слайде).
Неподвижная геометрия
SKU-…-metal_a
Живёт под base_a. Имя совпадает с именем материала — один к одному.
Подвижная геометрия
SKU-…-metal_aa00G
Живёт под подвижным хелпером. Имя = материал + суффикс хелпера + G.
Как строится имя подвижного хелпера
Подвижный хелпер — это ось движения детали. Имя состоит из двух частей: названия (придумывает моделлер) и суффикса (автофикс расставляет).

Ссылка на родителя
Только прямой подвижный родитель: его буква + номер.
Если родитель — base_a, этот блок не нужен.
Почему H на конце?
Существующие проверки распознают копии объектов по числовому окончанию — _01, _02… Буква H на конце предотвращает ложное срабатывание проверки: slide_a00H не выглядит как копия slide_a.
Имя подвижной геометрии
Имя строится из трёх частей. Каждая часть несёт свою информацию:
SKU-CLIENT-CAR_SEAT-SR-metal_a
имя материала целиком
b00a00
суффикс хелпера без H
G

→  SKU-CLIENT-CAR_SEAT-SR-metal_ab00a00G
Примеры
Хелпер Материал Геометрия slide_a00H metal_a → …-metal_aa00G height_b00a00H metal_a → …-metal_ab00a00G seat_pan_c00b00H leather_a → …-leather_ac00b00G armrest_d01c00H leather_a → …-leather_ad01c00G headrest_f00e00H leather_a → …-leather_af00e00G
Почему G на конце?
По той же причине что и H у хелперов: без G числовой суффикс a00 выглядел бы как числовой суффикс копии объекта (_01, _02…) и срабатывали бы ложные ошибки в валидаторе.
Имя материала
Содержит имя сцены, тип материала и суффикс (_a). Читая геометрию — сразу ясно какой материал должен быть назначен.
Суффикс хелпера без H
Часть имени хелпера после последнего _ , без финального H.
Из height_b00a00H берём b00a00.
Неподвижная геометрия
Под base_a — имя просто равно имени материала, без добавок.
SKU-…-metal_a (нет суффикса, нет G)

Правила букв
• Внутри одного типа материалов: _a, _b… без пропусков
• metal_a и plastic_a — разные типы материалов, буква одна - ok
• Единственный материал типа → всегда _a
Текстуры — по материалу, не по геометрии

Важно
Если автофикс переименовывает материал (metal_b → metal_a), он автоматически переименует файлы текстур на диске и обновит пути в материале. Файлы текстур должны начинаться с имени материала.
Что исправляет автофикс «Fix SR Scene»
Запускает пять шагов последовательно. Моделлеру достаточно задать названия хелперов (slide, armrest…) — суффиксы и имена геометрии пересчитываются автоматически.
0
Создание base_a
Если base_a отсутствует — создаётся. Геометрия, висящая прямо под корневым хелпером, перемещается под base_a.
geo под корнем
→ base_a
1
Суффиксы хелперов
Название (slide, armrest…) сохраняется, суффикс полностью пересчитывается по структуре дерева: буквы, номера, ссылки на родителей.
armrest_x01H
→ armrest_d01c00H
2
Буквы материалов
Заполняет пропуски в буквенных суффиксах, переименовывает материалы и все текстурные файлы на диске.
metal_b → metal_a
+ файлы текстур
3
Имена геометрии
Рекурсивно пересчитывает имена всей геометрии: matName для неподвижных, matName + helperCore + G для подвижных.
→ leather_ad01c00G
4
Выравнивание пивотов
Пивот каждого меша выравнивается по пивоту родительского хелпера — рекурсивно по всей иерархии.
pivot geo ← pivot helper
Что делает моделлер сам
Задаёт названия хелперов (slide, armrest…), назначает материалы на меши, строит структуру родитель-потомок в иерархии.
